Pici architecture proposal · 30 August 2026

Fewer nouns.
Firmer boundaries.

A deliberately small object model for Pici. It does not turn every existing class suffix into architecture. It identifies where state lives, who owns it, what crosses a boundary, and which objects exist only for one operation.

4 + 3

Four long-lived archetypes: runtime, aggregate, store, adapter. Three transient shapes: operation, projection, value. Domain names say what a thing is; archetypes say how it lives.

The object archetypes

Only four categories describe long-lived objects. The other three describe things passed between them. A type does not earn a new architectural noun merely because it has methods.

Long-lived · Runtime

A live activation scope

Owns mutable objects, workers, cancellation, and teardown whose lifetimes match one externally meaningful activation.

Pici use: SessionRuntime, the live incarnation of a durable session.

Constraint: do not use “runtime” for arbitrary mutable helpers.

Long-lived · Aggregate

A domain consistency boundary

Owns related in-memory state and enforces the invariants that must change together. Exposes domain operations.

Pici use: model catalog, authentication, mailbox, agent, task tree.

Naming: use the domain name; never add an Aggregate suffix.

Long-lived · Store

A durable authority

Owns durable reads, writes, transactions, synchronization, schema, and migration for one persistence boundary.

Pici use: SessionStore, MailboxStore, CredentialStore.

Constraint: a replaceable cache is not a store.

Long-lived · Adapter

An external boundary

Translates domain values to or from a wire protocol, terminal, interpreter, or remote provider.

Pici use: CLI, ACP, JSONL RPC, provider protocols, OAuth. A renderer is a nested output adapter used by a frontend.

Constraint: adapters do not own domain policy or durable truth.

Transient · Operation

One bounded execution

Has a start, result, failure behavior, and optional cancellation. It is owned by a runtime or aggregate.

Examples: agent run, catalog refresh, model pick, compaction.

Transient · Projection

A consumer-shaped read model

Derived and read-only. It may be immutable and point-in-time, but “snapshot” is a qualifier rather than its architectural identity.

Examples: model catalog view, session listing, task status view.

Transient · Value

Typed data without a lifecycle

May carry identity, configuration, intent, results, or observations. It owns no threads, persistence, or network behavior.

Examples: model key, model, request auth, provider report.

The rule

Domain names explain responsibility. Archetypes explain ownership and lifetime. ModelCatalog is an aggregate; it does not need to be called ModelCatalogAggregate.

What this rejects

Service, Coordinator, Manager, Registry, Resolver, and Controller are not architecture by default. They may describe private implementation techniques, not top-level boundaries.

Where everything lives

The OS process is the top owner. Process-owned aggregates and adapters outlive individual session activations. A session runtime owns only the mutable objects tied to that activated session.

Why Runtime survives

It is restricted to a live counterpart of a durable or externally identified scope. SessionRuntime qualifies. HookRuntime and MemoryStatsRuntime do not; they should become domain objects or private implementation state.

4 · Spawn and complete a child task

The task tree owns child lifetime. A child runtime owns separate mutable state and normally a separate durable session.

Interactions and call direction

Containment answers “who owns this?”; arrows answer “who may call whom?” Frontends initiate domain operations. Domain objects emit typed facts and results. Output adapters present those facts but never drive domain state by parsing presentation.

The model subsystem

One process-owned aggregate presents one coherent model inventory. Provider reporting, caching, merging, resolution, and publication stay behind that boundary instead of becoming separate top-level “services.”

ModelCatalogStarts a refresh for selected providers.
Catalog refreshRuns bounded, cancellable queries with partial-failure handling.
Discovery adapterCalls the provider-specific endpoint and parses its wire response.
Provider reportNormalized observations plus authority and freshness metadata.
Merge invariantsCombines built-in, reported, and configured layers.
ModelCatalogViewImmutable generation for lookup, listing, and presentation.
SessionRuntimeUses the catalog only when activating or explicitly selecting.
Aggregate · ModelCatalog

One public boundary

Owns provider definitions, catalog layers, current generation, merge precedence, refresh state, and model resolution.

Its report cache is private because cache mechanics are not a domain boundary.

Entity/value · Provider

Configuration, not a god object

Contains provider identity and endpoint plus explicit discovery, inference, and authentication bindings.

Bindings may share implementations, but behavior is always selected through the Provider.

Adapter · Protocol

Inference stays separate

Builds provider requests and translates streamed responses. Multiple providers may share one inference protocol adapter.

It does not discover or select models.

“Supported” must always be qualified

Reported means a provider advertised it. Known means it exists in the catalog. Selectable means it resolves into an effective model. Request-usable additionally means its protocol and authentication are available. These are different facts.

The picker is an operation

The picker is not another subsystem and does not own catalog truth. Native V1 and a later Lua UI implement the same bounded input/output contract.

Neither picker owns

Credentials, network concurrency, catalog merging, model resolution, idle-state validation, durable session metadata, or the active model transition. Those remain native aggregate/runtime behavior.

Selection to provider request

Each arrow crosses one explicit contract. The catalog resolves identity, the session commits selection, authentication supplies request credentials, and a protocol adapter owns the wire.

ModelCatalogResolves the key against its current generation.

Catalog refresh is process-scoped

Installing a new catalog generation never changes an active session implicitly. It affects later lookup, activation, picking, and explicit selection.

A turn is request-scoped

Each turn retains immutable model, context, and credential values. A refresh or later model switch cannot mutate an in-flight provider request.

The naming test

Before adding a top-level object, answer these questions in order. If none applies, it is probably a value, a private helper, or a method—not a new architecture noun.

Does it represent one live activation scope?

It owns workers, cancellation, mutable members, and teardown tied to a durable or externally meaningful identity.

YES → RUNTIME

Does it enforce one set of domain invariants?

Related state must change consistently behind one API and one ownership boundary.

YES → DOMAIN-NAMED AGGREGATE

Is it the durable authority?

It owns persistent reads, writes, transaction rules, schema, and migrations.

YES → STORE

Does it cross an external boundary?

It translates a wire protocol, terminal, remote endpoint, file format, or interpreter boundary.

YES → ADAPTER
Otherwise · bounded behavior

Operation

If it has a start and result, make it an operation owned by one of the four long-lived archetypes.

Otherwise · derived read data

Projection

If it exists for a reader and is derived from owned state, make it a projection.

Otherwise · typed data

Value or private helper

If it has no independent lifecycle or authority, keep it as data or an implementation detail.

01

Containment before naming. State who owns an object and when it dies before choosing its name.

02

One authority per fact. Aggregate state, durable state, and projections must not compete as truth.

03

Operations do not become subsystems. Refresh, pick, resolve, and compact remain bounded work.

04

Adapters do not decide policy. They translate boundaries and return typed facts or failures.

05

Projections are disposable. Consumers can retain a generation, but owners may publish a newer one.

06

Implementation helpers stay private. A map of factories does not automatically become a public registry concept.
