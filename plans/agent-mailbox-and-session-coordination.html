pici architecture brief · proposed

A mailbox for parallel agents

A Lua-first coordination layer that lets independent pici sessions find one another, exchange durable messages, and steer active agents between turns—without turning SQLite into the agent runtime or the transcript store. A2A remains an optional interoperability edge over the same high-level coordination intentions.

SQLite + WAL workspace scoped lease based at-least-once delivery Lua-defined tools one worker per process optional A2A edge

01 · Thesis

Make sessions visible before making them autonomous.

The highest-leverage first step is not remote process control. It is a shared, reliable directory of active pici sessions plus a narrow message channel. Once those primitives exist, Lua can decide what coordination policy the model sees.

Discover

Who else is working?

List live root sessions and subagents in the same workspace, including status, model, ownership, and liveness.

Address

Where should this go?

Target a durable session when restart tolerance matters, or a particular live activation when precision matters.

Coordinate

What should happen next?

Send an inbox note or a steering message that enters the recipient's context at its next safe turn boundary.

!

The database is a rendezvous point, not an agent scheduler.

SQLite records presence and envelopes. The existing C++ runtime still owns execution, cancellation, tools, model calls, and session journals.

02 · Boundary

There are already agents in pici—but only inside one process.

Today, pici.agents closes over one in-memory AgentTaskManager. It is excellent for a root agent and its child tasks. It cannot discover another pi-cli process. The mailbox should complement that API, not silently redefine it.

03 · Architecture

Keep policy in Lua and correctness in C++.

Lua gets safe, JSON-shaped operations. C++ owns SQLite transactions, locks, leases, lifecycle, and agent-loop integration. The model sees tools registered by a shipped Lua addon—not database methods.

04 · Identity

One conversation can have more than one live body.

A session ID names durable history. An agent ID names this particular activation of that history. Conflating them makes restarts, crashes, and duplicate attachment impossible to reason about.

Durable identity session_id = 01JSESSION…

Survives process exit. Addresses a conversation and its JSONL journal. Messages may wait here while no process is alive.

may have
many →
Ephemeral identity agent_id = agent_01J…

Random for each activation. Owns a lease, PID metadata, current status, and exact-instance routing.

Activate a durable session

Create a fresh agent ID and register status starting.

Advertise presence

Heartbeat every two seconds; refresh status, model, and a ten-second lease.

Switch sessions

Close the old activation and create a new agent ID rather than moving one identity between transcripts.

Crash or exit

Clean shutdown marks the row closed. A crash is detected when the lease expires.

↯

Duplicate attachment must be visible.

If two processes open the same session, listing returns both. The first release should require an exact agent_id before sending automatic steering to a multiply attached session.

Process identity

One lease covers every endpoint hosted by a process.

A random process_id owns the heartbeat. Root agents and subagents have separate agent_id endpoint rows that reference it. If the process lease expires, every endpoint it owns becomes stale together.

05 · Subagents

Completed is reusable. Closed is gone.

A child agent does not disappear when it finishes an answer. Its runner remains resident inside AgentTaskManager, ready for follow-up work. The mailbox mirrors that reality instead of treating completion as process death.

                       └── explicit close → closing → shutdown → removed
Running

Steer between turns

The owning process routes the envelope through a new AgentTaskManager::steer path. Current response/tool work reaches a safe boundary first.

Completed

Reactivate with follow-up

A message or request queues another work item on the existing child, reserves execution, and transitions it back to running.

Closing

Reject new delivery

Once close begins, messages fail as unavailable. On AgentTaskClosedEvent, the endpoint is marked closed in SQLite.

Why store a generation table when SQLite already has row IDs?
A waiter needs one monotonic cursor spanning both presence and message changes. SQLite has no portable cross-process condition variable. The event generation prevents a poller from missing a change that occurs between “inspect state” and “begin waiting,” while bounded polling provides the wake-up mechanism.
Why not put transcripts in SQLite too?
That would multiply the migration and recovery surface. Session JSONL already provides replayable history. The mailbox should prove cross-process coordination before it becomes a general persistence rewrite.
07 · Delivery

“Delivered” must mean the agent loop accepted it.

The poller observing a row is not delivery. Calling Agent::steer is not delivery either. A message is acknowledged only after the loop appends and publishes it at a safe boundary, immediately before the next model turn.

Sender commits

Insert the envelope and corresponding generation event in one transaction.

Receiver claims

Set a random claim token and expiry. Other receivers skip the live claim.

Coordinator steers

Queue an envelope-aware user message; do not mutate live model context from the polling thread.

Current safe unit finishes

The active assistant response and tool batch reach TurnEndEvent.

Loop accepts and acknowledges

Append the framed mailbox input, publish it, acknowledge with the claim token, then begin another model turn.

[Mailbox message 01JMSG… from session 01JSESSION… / agent agent_01J…]
Please inspect the auth resolver and send me the result.
steer

Cooperative interruption

If the target is running, enter its context at the next safe boundary. If it is idle, leave the message pending until an explicit run or inbox read.

note

Inbox only

Durable information that is never automatically injected. The recipient or a Lua tool chooses when to read and acknowledge it.

↩

Request/reply is correlation layered over delivery.

A request is a steering message with a stable ID and an expected response. A reply stores that request ID in reply_to_message_id. The sender waits only for that correlated reply—not for an arbitrary mailbox change.

request 01JREQ… ──steer──▶ recipient session
       ▲                         │
       └──── reply_to=01JREQ… ───┘

default wait: 30 seconds
maximum wait: 60 seconds
timeout result: { state = "pending", request_id = "01JREQ…" }
late reply: retained in the sender's inbox

A timed-out request is not cancelled. The waiting tool returns control to the model, and any later response remains durable. This prevents a coordination call from pinning an agent turn indefinitely.

08 · Lua first

Expose primitives; let Lua define the product.

The native layer should be boring and stable. A shipped addon converts those operations into concise tools the model understands, and can evolve naming, descriptions, and policy without recompiling the runtime.

Native Lua API

pici.mailbox.*

self, list, send, request, reply, inbox, ack, wait, and status. JSON-compatible arguments; nil, error on expected failures.

Model-visible addon

Coordination tools

Five mailbox intentions—agents_list, agents_send, agents_request, agents_reply, and agents_inbox—plus local-only agents_close.

local peers, err = pici.mailbox.list({
  include_self = false,
  include_stale = false,
  limit = 100,
})

local receipt, err = pici.mailbox.send({
  target = { session_id = "01JSESSION..." },
  text = "Please review the mailbox schema.",
  kind = "steer",
})

local reply, err = pici.mailbox.request({
  target = { session_id = "01JSESSION..." },
  text = "Find the cause and report back.",
  timeout_ms = 30000,
})
✓

The tool schema is the first capability prompt.

Start with excellent names, descriptions, target semantics, and errors. Only add a global system-prompt fragment if experiments show the model cannot discover the tools reliably.

09 · Agent exposure

The agent gets intentions, not mailbox machinery.

The full native API is available to trusted Lua addons. The default agent toolset deliberately omits claims, acknowledgements, generations, health checks, and raw waiting. Those details are composed inside the bundled addon.

Hidden from the model

Delivery bookkeeping

claim, ack, claim tokens, event generations, leases, raw wait, and database status stay below the tool boundary.

Why this matters

A smaller reasoning surface

The model decides whether to discover, inform, delegate, respond, or inspect. It never has to reason about WAL locks or delivery receipts.

Out-of-box exposure path

Mailbox participation remains an explicit capability, but once enabled it requires no manual addon installation.

[mailbox]
enabled = true
  1. pici opens and migrates mailbox.sqlite3.
  2. The current session registers presence and starts heartbeat/inbound delivery.
  3. The runtime installs the native pici.mailbox.* bindings.
  4. pici automatically loads its bundled mailbox.lua addon.
  5. The addon registers the five curated mailbox tools in the model context.
  6. The addon also registers local-only agents_close, backed by the existing recursive task-manager close path.
≠

Enabled does not mean globally visible.

Default discovery and sending remain scoped to the canonical workspace. Cross-workspace visibility requires an explicit configuration decision.

10 · A2A interoperability

Mailbox is the local kernel. A2A is an edge transport.

A2A should not change what a mailbox row means. It adds a bridge for external, independently implemented agents: Agent Cards for discovery, Tasks for durable work, Parts for typed inputs, Artifacts for outputs, and HTTP/SSE for transport.

The terminal-state mismatch drives the design.

A completed pici subagent is reusable. A completed, failed, canceled, or rejected A2A Task is terminal and cannot accept another message. One subagent may therefore execute many successive A2A Tasks; each new external unit of work receives a new taskId, optionally linked by one contextId.

Inbound A2A

pi-acp becomes the server edge

Authenticate the caller, resolve an explicitly exported capability, create a bridge Task, route it to a local endpoint, and translate pici events into status updates and final Artifacts.

Outbound A2A

A client behind the same agent intentions

Fetch an approved Agent Card, invoke Send Message, return a direct Message immediately, or track the returned Task and surface late completion through the local inbox.

Inbound request arrives

pi-acp validates authentication, Parts, extensions, sizes, and export policy.

Create bridge state

Persist separate A2A message, context, and task IDs plus the selected local endpoint.

Route locally

Send mailbox work to a root or subagent without publishing local IDs or workspace structure.

Translate progress

Map local execution to A2A Task status events; keep terminal semantics owned by the bridge.

Publish deliverables

Return outputs as Artifacts and close the A2A Task, while the reusable local subagent remains resident.

Bridge storage

Separate adapter tables

a2a_peers, a2a_task_links, and a2a_artifacts may share the SQLite file initially, but use modular migrations and store interfaces.

Model surface

One vocabulary, visible transport

agents_list returns transport = mailbox | a2a. Lua routes the existing send/request tools to pici.mailbox or trusted pici.a2a primitives.

Timeouts

Pending does not mean canceled

After 60 seconds, return the A2A taskId/contextId. Continue tracking so later completion arrives in the ordinary inbox.

Export policy

No automatic public directory

An Agent Card is generated only for explicitly configured capabilities. Session names, workspace paths, and transient subagent paths remain private.

Authentication

Discovery is not trust

Agent Cards describe capabilities. Authentication, tenant identity, authorization, and credential resolution remain separate from mailbox envelopes.

Content safety

Parts are untrusted inputs

Validate MIME type, size, file URLs, structured data, and extension URIs. Remote URLs require an explicit SSRF-safe fetch policy.

Cancellation

Cancel one bridge task

A2A Cancel Task may interrupt work owned by that bridge record. It never maps to generic agents_close or remote subtree destruction.

Recommended A2A delivery order
First implement outbound Agent Card parsing plus Send Message/Get Task. Then add durable correlation and late-result inbox delivery. Next add inbound Agent Card, Send Message, and Get Task to pi-acp. Add SSE streaming/subscription and artifact chunking afterward. Cancellation comes next; authenticated push notifications come last because they require retry and SSRF policy.

Protocol reference: the official A2A specification and its normative data model.

11 · Implementation hazards

The hard parts are all boundaries.

None of the individual APIs are especially exotic. Complexity appears where process lifecycle, database state, agent-loop state, and Lua callbacks meet.

Crash window

At-least-once means duplicates

A receiver can crash after context injection but before DB acknowledgement. Preserve a stable message ID and make redelivery explicit rather than claiming exactly-once semantics.

Lock ordering

Never call across layers while locked

Do not hold the SQLite store mutex while calling Agent::steer, a Lua callback, or an event observer. Claim, release, call, then acknowledge.

Foreground ownership

An idle CLI cannot wake itself casually

Readline owns the foreground input path. The background inbox pump should not invoke run_prompt on an idle interactive session in v1.

Identity ambiguity

A session may be multiply attached

Do not let two processes race to consume an automatic steering message invisibly. Require an exact activation target until routing policy is proven.

Shutdown order

The worker must die before its dependencies

The coordinator owns one std::jthread for heartbeat and polling. Stop and join it before destroying sessions, task managers, callback targets, or the SQLite store.

Trust boundary

Mailbox text is untrusted input

Inject it as an explicitly framed user message—not into the system prompt. Keep default visibility within the canonical workspace and database permissions at 0600.

Wait semantics

Wait for the reply, not activity

agents_request must correlate on reply_to_message_id. A heartbeat or unrelated note cannot satisfy the request.

Tool availability

Runtime and addon must agree

Enabling mailbox support must atomically provide native bindings and load the bundled addon. Partial availability should produce a clear startup diagnostic.

Resident growth

Completed children still consume slots

Do not hide this with immediate auto-close. Give the parent agents_close, document the resident limit, and consider an opt-in idle TTL only after real usage data.

Authority

Addressable does not mean killable

A remote agent may send work to a subagent endpoint. Only the owning process may interrupt or recursively close that task tree.

The envelope-aware steering change
Today, the steering queue carries bare Message values. The mailbox path needs a message plus delivery metadata and an acceptance action. Prefer a typed envelope with an optional acknowledgement callback or token. The agent loop invokes acceptance only after it has appended and published the input. The callback must be best-effort and execute without agent locks held.
SQLite polling without a busy loop
Use the monotonic event generation as the cursor, sleep in stop-aware intervals, and query only when the cursor may have advanced. A 250 ms default is responsive enough for local coordination and configurable for users who value fewer wakeups.
Database corruption and schema skew
Never silently recreate or truncate the mailbox. A newer schema should fail closed with a clear path and version diagnostic. Corruption recovery is an explicit operator action; ordinary chat may continue with mailbox features disabled.

13 · Before coding

Lock the remaining product semantics early.

Recommended defaults

These choices keep the first implementation narrow while leaving clear extension points.

  1. Require [mailbox] enabled = true, then load the bundled Lua addon automatically.
  2. Require an agent_id when one session has multiple live activations.
  3. Use the resolved context/workspace root as the isolation boundary.
  4. Show a small unread count to the human, but do not auto-run an idle CLI.
  5. Drain queued steering messages when an explicit agent run starts.
  6. Bound agents_request waits to 60 seconds and retain late replies in the inbox.
  7. Use exactly one maintenance worker per process; subagents inherit process liveness.
  8. Keep completed subagents resident until local explicit close, ancestor close, or shutdown; no automatic TTL in v1.
  9. Use system SQLite first and document it as a build dependency.
  10. Keep A2A optional and downstream of mailbox correctness; never put remote agents in the local heartbeat directory.
  11. Require explicit Agent Card export, authentication, and a new A2A taskId for each external unit of work.
Done means

Two real processes coordinate

They discover roots and subagents, exchange durable messages through Lua, recover an expired claim, and steer or reactivate the correct recipient.

Still unchanged

Existing foundations survive

Child-agent behavior, JSONL transcripts, terminal ownership, provider auth, and ordinary operation with mailbox disabled remain compatible; A2A stays an optional edge.
